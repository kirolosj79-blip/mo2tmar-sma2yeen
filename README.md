# ساحة المؤتمر · كنائس زويلة

نسخة **Next.js + Supabase** من داشبورد المؤتمر، منظمة كمشروع Clean Code (lib / components / app) وجاهزة ترفعها على GitHub وتنشرها على Vercel.

## بنية المشروع

```
conference-dashboard/
├─ supabase/
│  └─ schema.sql          ← السكيما الكاملة + RLS + بيانات ابتدائية
├─ src/
│  ├─ app/                ← صفحات Next.js (App Router)
│  │  ├─ dashboard/       ← الرئيسية: KPIs + ترتيب الفرق + رسومات
│  │  ├─ leaderboard/     ← الترتيب العام مع بحث وفرز
│  │  ├─ attendance/      ← الحضور العام
│  │  ├─ time/            ← حضور موقّت للأنشطة (قداس/حصة/ورشة) بنافذة مكافأة
│  │  ├─ bonus/           ← نقاط إضافية + سجل تدقيق
│  │  ├─ settings/        ← إدارة الفرق/الأنشطة/الأدمنز/إعدادات النقاط
│  │  └─ layout.tsx       ← RTL + خطوط + Toast + Stage providers
│  ├─ components/
│  │  ├─ layout/          ← Header (البراند + الناف + شريط اختيار المرحلة), AppShell
│  │  ├─ ui/               ← Card, Badge (عناصر واجهة عامة)
│  │  └─ charts/           ← PieChart, BarChart, ProgressRing
│  ├─ lib/
│  │  ├─ supabase/         ← client.ts (متصفح) و server.ts (سيرفر)
│  │  ├─ queries.ts         ← كل نداءات قاعدة البيانات في مكان واحد
│  │  ├─ export.ts          ← تصدير Excel / PDF
│  │  ├─ types.ts           ← أنواع TypeScript تطابق جداول Supabase
│  │  └─ utils.ts           ← دوال مساعدة مشتركة
│  └─ hooks/
│     ├─ useToast.tsx       ← إشعارات Toast (بديل toast() الأصلية)
│     └─ useStage.tsx       ← اختيار المرحلة (ابتدائي/إعدادي/ثانوي/الكل) — بيفلتر كل الصفحات
├─ package.json
└─ .env.example
```

## 1) تجهيز Supabase

1. اعمل مشروع جديد على [supabase.com](https://supabase.com).
2. من **SQL Editor** شغّل محتوى `supabase/schema.sql` مرة واحدة — ده هيعمل كل الجداول، الـ RLS، والبيانات الافتراضية (الفرق، الأنشطة، الأدمنز).
3. من **Project Settings → API** خد:
   - `Project URL`
   - `anon public key`

> ⚠️ سياسات الـ RLS في `schema.sql` مفتوحة (public read/write) عشان تشتغل فورًا للتجربة. قبل ما تستخدم المشروع فعليًا في مؤتمر حقيقي، فعّل Supabase Auth واربط السياسات بـ `auth.uid()` أو أدوار admin/viewer.

## 2) التشغيل محليًا

```bash
npm install
cp .env.example .env.local
# افتح .env.local وحط NEXT_PUBLIC_SUPABASE_URL و NEXT_PUBLIC_SUPABASE_ANON_KEY
npm run dev
```

افتح http://localhost:3000

## 3) رفعه على GitHub

```bash
git init
git add .
git commit -m "Initial commit: conference dashboard (Next.js + Supabase)"
git branch -M main
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main
```

`.env.local` مش هيترفع لأنه موجود في `.gitignore` — ده مقصود، مفاتيح Supabase بتتحط في Vercel نفسه (خطوة 4).

## 4) النشر على Vercel

1. من [vercel.com](https://vercel.com) → **New Project** → اختار الـ repo.
2. Framework Preset هيتعرف تلقائي على Next.js.
3. في **Environment Variables** ضيف:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. Deploy.

كل push جديد على `main` هيعمل نشر تلقائي.

## ملاحظات مهمة

### تحديث كبير (أنشطة مجمّعة، بونص منفصل، صفحة حضور واحدة)

- **صفحة "الخدام" جديدة** — قائمة وحضور وغياب ونسبة مستقلة تمامًا عن نظام النقاط والفرق (مبتأثرش على أي ترتيب أو مجموع). فيها تصدير Excel/PDF.
- **"حصة" بقت من ١ لـ ٧** بدل ١-٣ فقط.
- **اللوجو الجديد** (لوجو مدرسة السماعيين) اتحط في الهيدر والـ favicon.
- **الباسورد كان فيه باج** — لو `NEXT_PUBLIC_APP_PASSWORD` مش موجود، كان بيفتح الصفحة لأي حد بدون ما يطلب باسورد أصلاً. اتصلح: دلوقتي لازم الباسورد يتظبط صح في **Vercel → Settings → Environment Variables** (مش بس `.env.local` المحلي عندك) **وتعمل Redeploy بعدها** — لأن `NEXT_PUBLIC_*` بتتحط جوه الكود وقت البناء (build)، مش وقت التشغيل، فلازم بناء جديد بعد أي تغيير في الباسورد.
- **زرار حذف جلسة** ظهر في صفحة "تحليل الحضور" جنب كل تاب يوم (× صغيرة) — لمسح جلسات التجربة.
- **"حصة" رجعت لـ ١-٣** بدل ١-٧ (كانت مؤقتة).
- **صفحة "الخدام" بقت محمية بباسورد** زي تحليل الحضور والإعدادات، وبقى فيها **تسجيل حضور بالفقرة** (نفس نظام المشاركين بالظبط: قداس/حصة/ورشة...، جلسة يومية منفصلة) بس من غير أي نقط، وتحته "تحليل حضور الخدام" بنفس فكرة صفحة تحليل الحضور.
- **زرار "صفّر كل الدرجات"** في آخر صفحة الإعدادات (منطقة حمراء) — بيمسح كل تسجيلات حضور الأنشطة ويصفّر بونص الأفراد والفرق، من غير ما يمسح الأسماء أو الفرق نفسها. فيه تأكيد مرتين قبل ما يتنفذ.
- **الاسم بقى "مؤتمر تي ثيؤطوكوس"** بدل "ساحة المؤتمر" في الهيدر وعنوان الصفحة.
- **الأنشطة بقى ليها ترتيب ظاهر (يوم فعلي):** قداس → حصة ١ → ورشة ١ → ورشة ٢ → حصة ٢ → عشية → حصة ٣ → تسبحة. "كلمة سيدنا" مخفية افتراضيًا من كل التابات — تقدر تفعّلها وقت ما تحب من **الإعدادات → الأنشطة** (زرار "متوقف" جنبها).
- **عمود "الحضور" في الترتيب العام كان فيه باج** — كان بيوري رقم قديم ثابت صفر (`general_points`، ميزة اتشالت من زمان). دلوقتي بيوري نقط الأنشطة الحقيقية (`activity_points`).
- **أنيميشن خفيف** اتضاف للكروت (ظهور تدريجي + حركة بسيطة عند الـ hover) ولكل الأزرار/اللينكات (تأثير لمس بسيط) عشان الواجهة تحس أكتر إنها حية مش ثابتة.
- **إصلاح باج خطير:** صفحة "أنشطة الوقت" وصفحة "الخدام" بيستخدموا نفس نظام الجلسات — لو نشاط اتقفل في صفحة، وحد بدأ نفس النشاط تاني من صفحة تانية، كان بيتعمل جلستين لنفس اليوم بنفس الاسم بالظبط ("النهاردة")، وده كان ممكن يخلي حد يمسح الجلسة الغلط بالغلط. دلوقتي: (١) بيطلعلك تحذير واضح قبل ما تبدأ جلسة لو فيه جلسة اتعملت بالفعل للنشاط ده النهاردة، و(٢) لو اضطريت تعمل جلستين لنفس اليوم، التابات بتوضح رقم الجلسة (زي "النهاردة (جلسة ٢)") عشان تقدر تفرّق بينهم بسهولة قبل ما تمسح أي حاجة.
- **إصلاح باج جذري خطير:** جلسات الخدام كانت بتستخدم **نفس جدول جلسات المشاركين** — ده كان بيسبب: (١) نسبة الحضور في الترتيب العام بتتحسب غلط (لأن جلسات الخدام كانت بتتحسب ضمن إجمالي جلسات المشاركين)، و(٢) قفل جلسة من صفحة الخدام كان بيقفلها كمان عند المشاركين لأنها نفس الصف حرفيًا في القاعدة. دلوقتي الخدام ليهم **جدول جلسات مستقل تمامًا** (`khodam_sessions`) — مفيش أي تداخل خالص بين الصفحتين بعد كده.
- **صفحة النقاط الإضافية:** زرارين واضحين "إضافة (+)" و"خصم (-)" بيتحكموا في إشارة النقطة تلقائي، بدل ما تكتبها يدوي.
- **الحصان الأسود اتصلح:** كان بيعتمد بس على البونص الإضافي (نادر الاستخدام)، فكان دايمًا فاضي. دلوقتي بيحسب من نقط الأنشطة + البونص مع بعض، فهيظهر أي يوم فيه حضور فعلي.
- **الداشبورد:** بار تشارت "ترتيب الفرق" بقى أكبر عنصر في الصفحة (وبأرقام ظاهرة فوق كل عمود)، وكارت "تحليل حضور النشاط الحالي" (الـ pie) بقى أصغر وجنب البوديوم، وبرضه بأرقام ظاهرة جوه كل شريحة.
- **⚠️ قاعدة بيانات حقيقية شغالة؟** شغّل الميجريشنز الجديدة بالترتيب (لو لسه مشغلتهاش): `006_revert_lessons_and_khodam_sessions.sql` ثم `007_activity_order_and_active.sql` ثم `008_separate_khodam_sessions.sql` (بيرحّل أي بيانات حضور خدام قديمة لجدولها المستقل الجديد من غير ما يفقد حاجة).
- **مشروع جديد من الصفر؟** `supabase/schema.sql` فيه كل حاجة جاهزة من الأول، متحتاجش تشغّل الميجريشنز.
- **الأنشطة بقت مجمّعة:** حصة ١/٢/٣ وورشة ١/٢ بقوا أنشطة منفصلة تحت مجموعة واحدة (تظهر كتابات فرعية في صفحة الحضور)، وضفنا عشية وتسبحة وكلمة سيدنا جنب القداس. تقدر تضيف/تعدّل الأنشطة والمجموعات من **الإعدادات**.
- **نقطة الجلسة قابلة للتحكم:** في صفحة **الحضور**، قبل ما تدوس "ابدأ اليوم" تقدر تحدد مدة النافذة وقيمة النقطة (10/15/20...) — نفس القيمة بتتطبق على كل المراحل. بعد ما الوقت يخلص، النقطة بترجع تلقائي للقيمة الثابتة المتظبطة في الإعدادات.
- **بونص الفريق منفصل عن الأفراد تمامًا:** لما تدي بونص لفريق من صفحة "النقاط الإضافية"، بيتسجل على الفريق نفسه بس ومبيأثرش على نقط أي فرد فيه. نقط الفرد الشخصية (فردي) منفصلة تمامًا.
- **اختيار كذا مشارك مرة واحدة:** في صفحة "النقاط الإضافية"، قسم "مشارك/أفراد" بقى فيه قايمة بـ checkboxes — تقدر تختار أكتر من واحد وتدّيهم نفس النقطة مرة واحدة، وكل واحد نقطته بتتسجل منفصلة.
- **صفحة "الحضور العام" اتشالت خالص** بناءً على طلبك — بقى في صفحة واحدة بس اسمها "الحضور" (كانت "أنشطة الوقت") وهي بتغطي كل الحضور (عام ولحظي) للأنشطة.
- **الإعدادات → المشاركين:** لو اخترت "كل المراحل" من الشريط فوق، هتشوف كل فريق ومعاه أعضاءه مقسمين تلقائيًا حسب المرحلة (ابتدائي/إعدادي/ثانوي) في نفس الشاشة.
- **تحليل حضور الأنشطة** في لوحة العرض العامة بقى قابل للدوس عليه — بيوريك عدد اللي حضروا بدري، عدد اللي جم متأخرين، وعدد الغايبين، ولو دُست تشوف **أسماءهم بالظبط**.

- التصميم الأصلي (الألوان الذهبية/التركواز، الخط Tajawal/Manrope، الدارك مود، RTL) اتنقل هنا في `globals.css` و `tailwind.config.ts`.
- **أفضل ١٠ في كل مرحلة:** كارت جديد في لوحة العرض العامة بيوري أعلى مشارك وأفضل ١٠ مشاركين في **كل مرحلة على حدة** (ابتدائي/إعدادي/ثانوي) في نفس الوقت — بغض النظر عن المرحلة المختارة فوق في الشريط، وبيتحدث لحظيًا كل ٥ ثواني زي باقي الصفحة.
- **الداشبورد (لوحة العرض العامة) بقى مطابق للملف الأصلي بالظبط:** نفس الترتيب — كارت "أعلى مشارك" بيدور لوحده على المراحل الثلاثة كل ٥ ثواني (بغض النظر عن المرحلة المختارة فوق)، بعده "الفريق الأول" و"الحصان الأسود" و"التارجت" (بيتحسب أوتوماتيك من مجموع نقاط كل الأنشطة)، بعدين تحليل حضور الأنشطة (بيرسون شارت لكل نشاط بألوان الفرق)، بعدين ترتيب الفرق (بار تشارت) والبوديوم (أفضل ٥ بشكل الأعمدة الحقيقي زي الأصل)، وفي الآخر قسم "أفضل ١٠ في كل مرحلة" (ده إضافة كنت طلبتها في المحادثة، سايبها تحت كبونص).
- **ملاحظة عن "الحصان الأسود":** النسخة الأصلية بتتبع تاريخ ترتيب الفرق عبر الوقت (snapshot كل ٢٠ ثانية) وترسم شارت لصعود الفريق. النسخة دي مبسّطة (أكتر فريق جمع بونص إضافي النهاردة) لأن التتبع التاريخي محتاج جدول جديد في القاعدة يسجل لقطة للترتيب بشكل دوري — قولي لو عايزني أضيفه فعليًا.
- **الموبايل:** الواجهة كلها مبنية بـ Tailwind responsive classes وبتترتب في عمود واحد على الشاشات الصغيرة (الكروت، الجداول، القوايم)، والقايمة العلوية بتتحول لهامبرجر ☰ على الموبايل.
- **بار تشارت حقيقي:** كارت "أفضل ٥ فرق" و"ترتيب الفرق" في لوحة العرض العامة بقوا Chart.js bar chart بدل الأشرطة النصية.
- **الأنشطة بتتكرر يوميًا (النهاردة/بكرة/بعد بكرة):** صفحة "أنشطة الوقت" بقى ليها جلسة منفصلة تلقائيًا لكل يوم لكل نشاط. دوس "ابدأ اليوم"، سجّل حضور، وممكن تقفل الجلسة قبل ما اليوم يخلص لو حبيت. تاني يوم (حتى لو نسيت تقفل جلسة إمبارح) هتلاقي جلسة جديدة فاضية أوتوماتيك — من غير ما بيانات الأيام اللي فاتت تتلخبط أو تضيع.
  - **لو المشروع ده أول مرة تظبطه:** `supabase/schema.sql` فيه نظام الجلسات جاهز من الأول.
  - **لو أنت أصلاً شغّلت `schema.sql` قبل كده وعندك بيانات حقيقية:** شغّل `supabase/migrations/002_sessions.sql` (مرة واحدة بس) في SQL Editor — مش هيمسح ولا نقطة من بياناتك الحالية، بس هيضيف نظام الجلسات فوقها. في أعلى كل صفحة في `Header.tsx` فيه شريط لاختيار المرحلة (ابتدائي / إعدادي / ثانوي / كل المراحل) — بيفلتر كل الصفحات (الداشبورد، الترتيب، الحضور، الوقت، الإعدادات) زي الأصل بالظبط. الصفحات اللي محتاجة مرحلة واحدة محددة (الحضور، أنشطة الوقت، إضافة مشاركين) بتوريك رسالة توضيحية لو اخترت "كل المراحل".
- **إضافة/تعديل المشاركين:** من صفحة **الإعدادات** → قسم "المشاركين" — لازم تختار مرحلة معينة الأول من الشريط فوق، وبعدين هتلاقي كل فريق وتقدر: تضيف اسم جديد، تعدّل اسم موجود، تنقله لفريق تاني، أو تمسحه.
- **لوحة العرض العامة** (`/dashboard`) بقت مطابقة للسكرين شوت: كارت التارجت، الحصان الأسود، الفريق الأول، أعلى مشارك، دونتس تحليل حضور الأنشطة، أفضل ٥ فرق، وترتيب الفرق الكامل — وبتتحدث أوتوماتيك كل ٥ ثواني.
- `supabase/schema.sql` دلوقتي بيزرع نفس روستر الأسماء الافتراضية اللي كانت في الملف الأصلي (٢٣ مشارك إعدادي + ١٦ ثانوي) موزعين على الفرق الأربعة، عشان الأرقام تتطابق مع اللي كنت شايفه.
- النسخة دي كمان فيها تصدير Excel/PDF من صفحة الترتيب العام (`lib/export.ts`) وتطبيق نقاط جماعية على مجموعة محددة من المشاركين (bulk points).
- لسه مش متضمن: الـ command palette (⌘K)، وضع "نقطة مختلفة لكل مشارك" في التطبيق الجماعي (الزرار موجود بس معطل حاليًا). تقدر تضيفهم تدريجيًا فوق نفس البنية — `lib/queries.ts` هو المكان اللي تضيف فيه أي نداء Supabase جديد.
- عايز اللغة الإنجليزية أو ثنائية اللغة؟ الطريقة الأسهل: كرر نمط `dict` من الملف الأصلي جوه `src/lib/i18n.ts` واستخدمه في الصفحات بدل النصوص الثابتة.
